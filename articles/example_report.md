# Example reports

Two reports from
[`render_report()`](https://thomuk.github.io/DBinventory/reference/render_report.md),
both run against the full [Fake NHS Trust synthetic
dataset](https://github.com/ThomUK/synthetic-hospital-data) read through
its `fakehospdata` package, leaving out its `answers` schema (the mess
log and truth tables are the dataset’s answer key, not part of the
trust’s warehouse). Each report is a single self-contained HTML page
with three tabs, one per phase, and every table in it can be filtered
and downloaded. They are regenerated by the `example-reports` workflow
on the repository’s Actions tab, run by hand.

| sampled | full set | 1,000,000 rows | 45 | 7 | 518 | 54,368,976 | Phase 1 only: this was a sampled check, where not every row of the largest tables was reviewed. The full check below shows phases 2 and 3. | 14 s | 2026-10-25 13:03 UTC |
| full | full set | none | 45 | 0 | 518 | 54,368,976 | Shown: 90 foreign key candidates and the table clusters | 17 s | 2026-10-25 13:03 UTC |

## Sampled report

The default way to run the package on a large warehouse. Every table is
inventoried and every column profiled, but tables above the sampling
threshold are profiled on a sample of their rows, so the run is quick
and the largest tables cost no more than the smallest. Phase 1 is
complete; the phase 2 and 3 tabs explain that a full check is needed for
clustering and keys.

[Open the sampled
report](https://thomuk.github.io/DBinventory/example-report-sampled.md)
(opens in a new tab, 2.3 MB, rendered 2026-10-25 13:03 UTC)

## Full report

Every row of every table is profiled, so distinct counts and uniqueness
are exact and phases 2 and 3 are produced: the table clusters with a
proposed canonical member for each group, the primary key candidates,
and the foreign key candidates with their evidence and confidence. On a
large SQL Server warehouse this is the slower run; on DuckDB and Parquet
it is usually the quicker one.

[Open the full
report](https://thomuk.github.io/DBinventory/example-report-full.md)
(opens in a new tab, 2.4 MB, rendered 2026-10-25 13:03 UTC)

To make one for your own database:

``` r

library(DBinventory)
inventory_run("Driver={ODBC Driver 18 for SQL Server};Server=...;Database=...;Trusted_Connection=yes;",
              organisation = "Your NHS Trust", store = "dw_inventory.sqlite", report = "dw_inventory.html")
```
